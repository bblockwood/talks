# Decisions

Newest last. Each entry: date, decision, why.

- **2026-11-26. `docs/native-spec.md` is a copy of `~/Repos/Lectern/SPEC.md`** at Lectern commit `304d946`. The file was missing from this repo, and SPEC.md says it is copied here. Re-copy if the native spec changes in a way that matters to the web version.
- **2026-11-26. Site URL is `https://benlockwood.com/talks/`.** The user site `bblockwood.github.io` has the custom domain `benlockwood.com` with HTTPS enforced, and has no `/talks` path of its own.
- **2026-11-26. UI layer is plain TypeScript for now** (no Preact). Revisit at W3 if the phone UI gets unwieldy.
- **2026-11-26. Relay URL and CSP origin come from `VITE_RELAY_URL`** in `.env.production` / `.env.development` (committed; not secret). The CSP `<meta>` is filled in from it at build time.
- **2026-11-26. PDF.js 6 needs Node ≥ 22.13** when run under Node. The browser build is unaffected. CLAUDE.md says tools need Node ≥ 20; if the publish tool ends up importing PDF.js (e.g. for the page count), that floor rises to 22.13. To settle in W2.
- **2026-11-26. Relay is at `wss://lectern-relay.bblockwood.workers.dev`**, with `ALLOWED_ORIGINS = https://benlockwood.com`. `npm --prefix relay run deploy` passes `--env=""` so it always targets the production (top-level) environment.
- **2026-11-26. SPEC §4.5 holds: `current.json` stays on Pages.** No need to move lookups to the Worker. `tools/w0-cachetest.mjs` replaced an already-cached `current.json` via the `decks` branch and `gh workflow run`; the new content was served 31 s and 36 s after the push in two runs, which is the workflow's run time. Pages sends `cache-control: max-age=600` but purges its CDN on each deploy, so even the URL without `?t=` returned the new file at the same moment. Keep `cache: "no-store"` plus `?t=` anyway: they are what gets past the *browser's* own 10-minute cache, which this Node test doesn't have. Caveat: measured from one location (Ben's Mac), so `--wait` in the publish tool remains the real safeguard.
- **2026-11-26. W1 entry screen is interim.** No talk codes exist until W2, so the entry screen offers the bundled test decks and a file picker ("Open a PDF from this computer", read into memory only). W2 replaces both with the code field of SPEC §5.1. The file picker is not in the spec; Ben to say whether it should survive W2 as a fallback (e.g. PDF on a USB stick when the network is down).
- **2026-11-26. Session logic is a port of the native `SessionReducer`** (`~/Repos/Lectern/Packages/PresenterCore`), with the same command names, so the wire `command` messages of SPEC §8.2 can be shared with the native app later. Browse, pointer, ink and timer commands are left for W3–W5.
- **2026-11-26. Leaving full screen does not end the talk, with one exception.** If the browser drops out of full screen (a stray Esc where keyboard lock is unavailable, or anything else), presenting continues in the window and the next key press re-enters full screen, since a key press is a valid user gesture. The exception is SPEC §5.3's "hold Esc": when the keyboard lock is on and full screen ends while Esc is down, the talk ends. Why: principle 1, never fail on stage; ending wipes the deck, which after W2 means retyping the code.
- **2026-11-26. Key map details the specs leave open** (Fable's choices; say if any should change):
  - Any key other than a digit, Enter or a bare modifier abandons a half-typed frame number.
  - Held next/previous keys auto-repeat; held Delete, B, W, F and Esc do not.
  - Home and End are not mapped (Native §6.5 doesn't map them).
  - Tab, L, D, C, T and ? are swallowed and do nothing until their features exist.
  - Cmd+[ and Cmd+] are back/forward as in Native; on Windows that is the Windows key, so Delete is the practical one there.
- **2026-11-26. Deck title in W1 is the PDF's own Title field**, else the file name. From W2 it comes from `meta.json`.
- **2026-11-26 (Ben). Talk codes are one talk-relevant word that Ben chooses**, e.g. `bunching`, not four random words. Ben values expediency over security. Consequence, accepted: anyone who guesses the word can open the slides and, from W3, drive them during the talk; a published deck should be treated as roughly public. `--random` (four EFF words) and `--long` (six) remain for a deck that needs more. If no code is given on first publish, the PDF's file name is used.
- **2026-11-26 (Ben). The file picker stays** on the entry screen as a permanent secondary option, next to the code field. The bundled test decks are shown in development builds only.
- **2026-11-26 (Ben). `@types/node` is an allowed dev dependency** (added to CLAUDE.md).
- **2026-11-26. Tools are TypeScript run directly by Node** (`node tools/publish.ts`, built-in type stripping), so they import the same `src/core` crypto and payload code the browser uses, with no build step. This needs Node ≥ 22.18, up from the "Node ≥ 20" in CLAUDE.md (now updated); PDF.js 6 needed ≥ 22.13 anyway.
- **2026-11-26. HKDF salt is empty.** SPEC §3 gives the `info` strings but no HKDF salt; the PBKDF2 step already carries the salt `lectern-web-v1`. Fixed by the test vectors in `fixtures/crypto-vectors.json`.
- **2026-11-26. Phone ink waits for W5** (SPEC §12 open question; §7 already places Draw mode in W5, and Ben did not ask otherwise).
- **2026-11-26. The phone shows what the room PC confirms, not what it asked for.** A tap sends a command; the phone's slide changes when the room PC's `state` comes back. This keeps one source of truth and makes a lost command visible, at the cost of one round trip (tens of milliseconds) before the phone's own picture changes.
- **2026-11-26. Gestures on the phone's current slide:** a quick horizontal swipe steps; press and hold for a third of a second, then drag, moves the pointer; a tap on a link follows it. SPEC §7 lists "long-press or drag" for the pointer and swipe for stepping on the same surface, which conflict, so drag alone is a swipe.
- **2026-11-26. Wire format details the spec leaves open:** `sid` is 64 random bits as 16 hex characters (a JSON number can't hold 64 bits); `state` also carries `forwardHistory` and, when it answers a command, `ack: {sid, seq}` so the sender can time the round trip. Every incoming message is rebuilt field by field before use.
- **2026-11-26. Notes in W3 cover the text sources** (sidecar overrides, `.pdfpc`, PDF text annotations, PowerPoint), merged as in the native app. The Beamer second-screen split is an image crop and comes with the presenter view in W4.
- **2026-11-26. T pauses and resumes the talk clock** on the room PC keyboard, as in Native §6.5. The clock starts at Start.
- **2026-11-26. Mode B window roles.** The window Ben starts from becomes the audience view, full screen on the chosen screen (`requestFullscreen({ screen })`), and the presenter view opens as a second window on the other screen from the same click (Chromium's "fullscreen companion window"). The audience window owns the session and the relay connection; the presenter window sends Commands. The two-click start (choose screens, then Start) exists because the permission prompt uses up the first click. None of this has run on real two-screen hardware yet.
- **2026-11-26. The decrypted deck reaches the presenter window over the BroadcastChannel**, which has a random name per talk passed in the presenter URL's hash. It stays in memory on the one machine, and the audience window drops its copy when the talk ends (or at Start in Mode A).
- **2026-11-26. Beamer notes-split decks: every page is its own frame.** Beamer's page labels are not frame numbers in such decks (`notes-right.pdf`: 5 frames labelled 1,1,2,2,3,3), and the native app left the question open. So "Frame N" is the page number there, and Shift+arrows step one page.
- **2026-11-26. The split is applied automatically and can be turned off on the entry screen**, instead of the native app's one-time question stored in the sidecar: the room PC stores nothing. Order of precedence: `--notes-split` at publish (or the sidecar's value), then pdfpc's hint, then the page shape. The phone follows whatever the room PC reports.
- **2026-11-26. Presenter layout is not saved** (pane divider, notes size): nothing is stored on the room PC. It resets each talk.
- **2026-11-26. Left out of the W4 presenter view, to revisit if Ben wants them:** the outline/table of contents in the notes pane (Native §4.4), the Frames/Builds toggle in the overview (Native §6.3), the countdown editor popover (the clock click pauses and resumes; Reset is a button), Swap displays (choose the screen before Start instead), and the "APPENDIX" badge (Native §4.2).
- **2026-11-26 (Ben). Swap displays added to Mode B**: a button in the presenter window, and Ctrl+D (Cmd+D on a Mac) in either window, as in Native §6.5. From the presenter window the click is handed to the audience window with `postMessage(…, { delegate: "fullscreen" })`, since only the audience window can move its own full screen; the presenter window is then moved to the other screen. If the browser refuses, the status bar says to click the slides and press the key there.
- **2026-11-26 (Ben). Phone in landscape shows only the controls**: the slide and notes are hidden and Prev/Next fill the screen, with the frame and clock above. Applies when the screen is under 540 px tall, so tablets in landscape keep the full layout.
